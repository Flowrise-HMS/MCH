# MCH Module

> Register pregnancies and child-welfare clients, capture ANC/CWC visit assessments, store anthropometry, run the EPI immunization schedule (vaccines, due doses, vaccination card), and issue client-held MCH books for FlowRise HMS.

The `MCH` module depends on `Modules\Core`, `Modules\Patient`, and `Modules\Clinical`. Appointment is an optional peer: ANC return dates (`AncReturnScheduler`) and EPI dose appointments (`EpiAppointmentScheduler`) are booked only when the Appointment module is enabled.

Verified against code on 2026-09-20.

This document is the canonical guide for the module. It is meant to be useful to:

- midwives and clinicians who need to understand pregnancy registry, CWC, and book issuance
- administrators who need to assign Shield permissions for the MCH cluster
- developers who need to extend MCH-1 without rebuilding work reserved for later phases

## Current Status

MCH-1 (registry, visits, anthropometry, books) and MCH-2 (immunization / EPI) are **complete** for operational use, together with the **MCH Workspace**.

What is available:

- pregnancy registry (`PregnancyEpisode`) with LMP/EDD, gravida/parity, risk factors, derived or overridden `RiskLevel`, and a "Record pregnancy outcome" action (`PregnancyOutcome`: active, delivered, referred_out, lost_to_follow_up, stillbirth, maternal_death)
- CWC registry (`ChildHealthRecord`) linked optionally to a pregnancy episode; a child registered with a mother gets a `patient_relationships` row (`type = mother`)
- ANC visit assessments on `EncounterType::ANTENATAL` encounters, including danger signs and optional fundal-height measurement
- CWC visit assessments on `EncounterType::CHILD_WELFARE` encounters, including feeding, vitamin A, deworming, and child anthropometry
- a shared `growth_measurements` store (child types plus obstetric `fundal_height`)
- vaccine catalogue (`Vaccine`, `VaccineAntigen`: BCG, OPV, pentavalent, PCV, rotavirus, measles-rubella, yellow fever, hepatitis B, tetanus toxoid), EPI schedules (`ImmunizationSchedule` / `ImmunizationScheduleItem`, Ghana EPI seed data) and `ImmunizationRecord` rows (`ImmunizationStatus`: scheduled, administered, declined, contraindicated) generated by `EpiDueService`, administered or declined through `ImmunizationRecordService`, with appointments auto-booked for scheduled doses
- printable **Vaccination card** page listing every child-schedule dose with its due/overdue classification
- client-held MCH book issuance and replacement with per-branch serials (`ANC-0001`, `CWC-0001`, ...)
- **MCH Workspace** (Workspaces sidebar group): search or register mother/child, home dashboard (ANC today, CWC today, EPI due/overdue, EDD within 14 days, high-risk pregnancies, books issued today, recent), and per-patient tabs
- FHIR `EpisodeOfCare` (read/search) and `Immunization` (read) mappings
- a Filament **MCH** cluster in the **Patient Care** sidebar group with nine resources, plus read-only relation managers on the patient record
- Shield policies for every resource model, seeded by `MchShieldPermissionsSeeder` (super_admin, doctor, nurse)

Explicitly out of scope (deferred to later phases, not missing work):

- MCH-3: WHO LMS Z-scores (`GrowthZScore` must read **only** child anthropometry rows, never `fundal_height`)
- MCH-4: delivery records, newborn auto-registration from a delivery record, `ChildHealthRecord.delivery_record_id` FK
- PNC (postnatal) visit assessments (postnatal encounters exist in Clinical but MCH has no PNC form)
- consent enforcement (`data_consented` is stored, never checked); do not claim GHILMIS/school-entry compliance until a flow reads it

## Mental Model

### The shortest explanation

MCH turns a **patient** into either a **pregnancy episode** (mother) or a **child health record** (child), then records **visit assessments** against Clinical encounters and optionally issues a **physical MCH book**.

```text
Patient
   │
   ├── PregnancyEpisode  ──► MaternalVisitAssessment (ANC encounter)
   │         │                        │
   │         │                        └── GrowthMeasurement (fundal_height)
   │         └── MchRecord (ANC book)
   │
   └── ChildHealthRecord ──► ChildVisitAssessment (CWC encounter)
             │                        │
             │                        └── GrowthMeasurement (weight, length, MUAC, HC)
             └── MchRecord (CWC book)
```

### Why this matters

- **Clinical owns the visit.** ANC/CWC assessments attach to existing `Encounter` rows of the matching type. MCH does not invent a second visit table.
- **Services own writes that have rules.** Visit capture, book issuance, risk derivation, and optional return scheduling go through `Classes\Services\*`. Filament create pages call those services instead of `Model::create()` for those flows.
- **Appointment is optional.** `AncReturnScheduler` must not hard-import Appointment classes; Core’s modular-ownership test guards that file.

## Data Model

All models extend `Modules\Core\Models\BaseModel` (auditing + `BelongsToBranch`) and use `HasUuids`. `PregnancyEpisode` and `ChildHealthRecord` also use `SoftDeletes`.

### Tables

| Table | Purpose | Soft deletes |
|-------|---------|--------------|
| `pregnancy_episodes` | One pregnancy per mother at a facility (LMP, EDD, risk, outcome) | yes |
| `child_health_records` | CWC registry row per child; optional link to pregnancy | yes |
| `growth_measurements` | Typed anthropometry / fundal height | no |
| `maternal_visit_assessments` | ANC visit findings on an antenatal encounter | no |
| `child_visit_assessments` | CWC visit findings on a child-welfare encounter | no |
| `mch_records` | Client-held book serials (morph owner = episode or CWC record) | no |
| `vaccines` | Vaccine catalogue (antigen, doses, route, ...) | no |
| `immunization_schedules`, `immunization_schedule_items` | EPI schedule definitions (child and maternal TT) | no |
| `immunization_records` | Scheduled / administered / declined doses per patient (batch, lot, site, appointment link) | no |

### One-active-book uniqueness (MariaDB 1901)

MariaDB 11.8 rejected a stored generated column on `CHAR` (`active_owner_key`, error 1901). One-active-book uniqueness is therefore **application-level**:

`MchBookIssuanceService` uses `DB::transaction` + `lockForUpdate` on the owner row **without global scopes**, then allocates the next serial under a branch-row lock (`MAX` under lock).

Do not re-introduce a CHAR-based generated unique column on this MariaDB version.

## Services

All service classes live in `Modules/MCH/app/Classes/Services` (`Modules\MCH\Classes\Services`), **not** `app/Services`.

| Class | Role |
|-------|------|
| `PregnancyRiskService` | Derives `RiskLevel` from risk-factor values |
| `MaternalVisitAssessmentService` | Records an ANC assessment; derives GA and visit number from the linked episode when omitted; writes fundal height into `growth_measurements` and BP/weight through Clinical `VitalSignService`; danger signs always set `referral_required` |
| `ChildVisitAssessmentService` | Records a CWC assessment plus child anthropometry rows |
| `MchBookIssuanceService` | Issues / replaces books; serial + one-active-book invariants |
| `AncReturnScheduler` | Optionally creates Appointment return dates (weekly recurrence every `mch.anc_returns.interval` weeks, `occurrence_count` occurrences) when that module is enabled |
| `EpiDueService` | Generates due `ImmunizationRecord` rows from the active schedules and classifies doses as due / overdue |
| `ImmunizationRecordService` | Administers (batch/lot, site, date) or declines a dose |
| `EpiAppointmentScheduler` | Books an Appointment for each scheduled dose (`mch.epi_appointments.*`) when the module is enabled |
| `MchWorkspaceService` | Workspace context resolution, home dashboard queries, open-encounter lookup / creation |

`PregnancyEpisode` still derives risk and booking GA in `saving` via `PregnancyRiskService` so Filament create/edit stay consistent without a dedicated pregnancy-create service. When `edd` is blank and `edd_source` is LMP, `saving` also derives EDD as LMP + 280 days.

`EpiDueService::generateDueRecords()` anchors child doses on the date of birth and maternal TT doses on the previous administered dose (dose 1 on the ANC booking date passed as `$anchorDate`), so a maternal dose is only generated once the one before it has been given. The workspace "Record pregnancy outcome" action closes the active episode by setting `PregnancyEpisode.outcome`; delivery details remain MCH-4.

`MchServiceProvider` resolves `pregnancyEpisodes`, `activePregnancyEpisode`, `childHealthRecord`, `immunizationRecords`, and `growthMeasurements` on `Patient` dynamically (the Clinical pattern) and registers three read-only relation managers on `PatientResource` through Core's `RelationManagersRegistry`.

The MCH Workspace registers patients through `Modules\Patient\Classes\Services\PatientService::create()` and its own Filament schemas (`registerForm`, `ancVisitForm`, `cwcVisitForm`), which reuse `quickElements()` from the resource form classes. A child registered with a mother gets a `patient_relationships` row (`type = mother`, subject = child, object = mother).

### MCH Workspace

`Filament\Clusters\Workspace\Pages\MchWorkspace` (URL `/mch-workspace/mch-workspace`, page title "Mch Workspace"). Verified in the UI on 2026-09-20:

- **Home**: patient search, **Register mother** / **Register child** buttons, and cards ANC today (n), CWC today (n), EPI due / overdue (n), EDD within 14 days (n), High-risk pregnancies, Books issued today, Recent.
- **Register mother**: sections Demographics (First name, Last name, Date of birth, Phone; gender is set to female), Booking (Gravida, Parity, LMP, EDD, Edd source LMP / Ultrasound, Multiple gestation, Booking date) and Risk (risk-factor checkboxes, Manual risk override); **Save** creates the patient and the pregnancy episode (EDD, GA and risk level derived). **Register child**: Demographics (First name, Last name, Date of birth, Gender, Phone, Mother (optional)); **Save** creates the patient, the child health record and, when a mother is chosen, the `patient_relationships` row.
- **Patient context** (`kind` = mother or child): tabs Overview, Encounter, Anc visit / Cwc visit, Immunizations, Growth (child), Vitals, Books, History. Header: the shared Clinical patient actions (Clinical Workspace, Timeline, View Full Profile, More Actions; Medication Canvas once an encounter exists) plus **Vaccination card** for a child. **Record pregnancy outcome** sits on the mother's Overview tab (Outcome: Delivered, Referred out, Lost to follow-up, Stillbirth, Maternal death); **Issue ANC book** / **Issue CWC book** sit on the Books tab (modal with a data-consent checkbox).
  - **Anc visit** form: Systolic BP, Diastolic BP, Weight, Visit number, GA weeks/days, Fetal heart rate, Presentation (Cephalic / Breech / Transverse / Oblique / Other), Edema, Urine protein, Urine glucose, Fundal height (cm), Return date, Danger signs, Drugs given, Referral required, Referral destination, Notes; **Save ANC visit** also creates the antenatal encounter (status arrived) when none is open.
  - **Cwc visit** form: Weight, Length / height, MUAC, Head circumference, Feeding (Exclusive breastfeeding / Mixed feeding / Complementary feeding / Other), Developmental screen (Normal / Concern / Referred), Vitamin A given, Dewormed, Referral required, Referral destination, Notes; **Save CWC visit**.
  - **Immunizations**: **Generate dues** (child) / **Generate TT dues** (mother) create `ImmunizationRecord` rows listed as *Vaccine · dose n · Scheduled* with **Administer** / **Decline** per row; inputs "Batch/lot for administer" and "Decline reason". Generating child dues also books one appointment per dose (09:00, 30 min) on the due date, or today when the dose is already overdue (a child registered late gets all pending doses booked for today). In the check, **Generate TT dues** for a newly booked mother produced no rows.
- Widgets: `PatientMaternalVisitsWidget`, `PatientChildVisitsWidget`, `PatientGrowthMeasurementsWidget`, `PatientImmunizationsWidget`.

### Permissions

Each model has a Shield-style policy registered from `MchServiceProvider` (`ViewAny PregnancyEpisode`, `Create MaternalVisitAssessment`, …). `MchShieldPermissionsSeeder` (run by `module:seed MCH` / `composer setup`) creates `View MchCluster`, `View MchWorkspace`, `View VaccinationCard` and the model abilities for all nine models and grants them to `super_admin`, `doctor` and `nurse`; other roles need the permissions assigned in Shield.

`data_consented` is a stored flag only; the workspace book action asks for it with a checkbox but no flow enforces it. The printable `VaccinationCard` page requires `View VaccinationCard` and lists every active child-schedule dose with its due/overdue classification.

## Administrator Guide

```text
1. Enable the MCH module (`modules_statuses.json` → MCH: true)
2. Run Core, Patient, Clinical, then MCH migrations and seeders (`php artisan module:migrate MCH --seed` seeds the Ghana EPI vaccines/schedules and the Shield permissions)
3. php artisan shield:generate --all --panel=corepanel --ignore-existing-policies (then assign permissions to roles other than doctor/nurse)
4. Open Workspaces → MCH Workspace (day-to-day) or Patient Care → MCH (registries and master data)
5. Register a pregnancy or CWC record, then capture visits; generate EPI dues and administer doses
6. Issue an MCH book from the workspace Books tab or Patient Care → MCH → MCH books (serials are per branch)
```

Configuration (`config/config.php`, env-overridable): `MCH_ANC_RETURN_TIMEZONE`, `MCH_ANC_RETURN_INTERVAL_WEEKS` (4), `MCH_ANC_RETURN_OCCURRENCES` (8), `MCH_ANC_RETURN_START_HOUR` (9), `MCH_ANC_RETURN_START_MINUTE`, `MCH_ANC_RETURN_DURATION_MINUTES` (30), `MCH_EPI_APPOINTMENT_START_HOUR` (9), `MCH_EPI_APPOINTMENT_START_MINUTE`, `MCH_EPI_APPOINTMENT_DURATION_MINUTES` (30). There is no MCH settings page and no scheduled command.

Useful commands:

```bash
php artisan module:migrate MCH --seed
php artisan test --compact Modules/MCH/tests
```

## Developer Guide

### Module boundaries

- Hard requires: Core, Patient, Clinical (`module.json`).
- Soft peer: Appointment (`AncReturnScheduler`, `EpiAppointmentScheduler` + Core `OptionalClass` / ownership test).
- `patient_relationships` lives in Patient; the workspace fills it (mother link) when a child is registered with a mother.
- `ChildHealthRecord.delivery_record_id` has no FK until MCH-4.

### Key classes

| Class | Role |
|-------|------|
| `Classes\Services\*` | Domain writes (see Services) |
| `Classes\Fhir\FhirEpisodeOfCareTransformer`, `FhirImmunizationTransformer` | FHIR EpisodeOfCare (read/search) and Immunization (read) |

## Summary

1. Services live in `app/Classes/Services`, never `app/Services`.
2. Enums implement Filament `HasLabel`, `HasColor`, and `HasDescription`.
3. Visit and book writes go through services; the Filament cluster is the operator UI.
4. One-active-book uniqueness is a transaction + row lock, not a generated column.
5. MCH-3/4 must not rebuild registry, assessments, anthropometry storage, immunization records, or book issuance.
